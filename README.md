# 프로젝트 주제 : 주식 매매 시스템 ( REST API 및 Spring Batch 기반 대용량 처리 )


# 프로젝트 개요
- 대규모 트래픽에서 발생하는 데이터 정합성( 동시성 ) 문제 방어와,
  금융 서비스의 핵심인 리스크 관리( 반대매매 ) 시스템 자동화에 역량 집중


# 핵심 로직 및 아키텍처 설계
- 동시성 제어 및 중복 진입 방어 ( MariaDB, Redis )
  다수 유저의 동시 매수 요청 시 경쟁 상태로 인한 예수금 초과 및 중복 차감 위험을 사전에 식별하고, 트랜잭션 순서를 보장하기 위해 비관적 락을 사용하여 금전 사고를 방지한다.
  DB 락 점유로 인한 병목을 막기 위해 락 범위 내에서는 예수금 차감 및 주문 데이터 생성만 수행하고, 증권사 API 통신은 트랜잭션 외부로 분리하여 서버 장애를 방지한다.

- 증권사 웹훅 수신 및 중복 요청 방어 ( JPA, Redis )
  외부망 장애나 지연으로 인한 웹훅 재전송 시, 주문이 이중 처리되는 상황을 방어할 수 있도록 설계한다.
  매번 DB를 조회하여 검증할 경우 부하가 발생할 수 있으므로, 메모리 기반인 가벼운 Redis를 활용하여 메인 DB 부하를 최소화한다.
  또한 단순히 체결 상태만 갱신하는 간단한 상태 업데이트 로직은 JPA의 변경 감지를 사용하여 개발 생산성을 높인다.

- 정산 배치 ( Spring Batch, MyBatis )
  거래가 몰리는 시간에 증권사로부터 체결 상태 수신 즉시 정산 로직을 실행하면 서버에 부하가 집중될 수 있다.
  이를 방지하기 위해 체결 내역을 DB에 1차 적재만 해두고, Spring Batch를 활용해 설정된 짧은 스케줄 주기에 따라 미정산 내역을 분할( Chunk ) 조회하여 일괄 정산 처리한다.
  쓰기 작업에는 메모리 부하가 큰 JPA 대신 MyBatis의 대량 일괄 삽입( Bulk Insert ) 방식을 적용하여 처리 성능을 극대화한다.

- 리스크 관리 자동화 ( 반대매매 배치 )
  정산 기한 내 미수금을 입금하지 않은 거래를 대상으로 시스템이 일괄 강제 청산( 반대매매 )을 집행할 때, 일반 매매 트래픽과 겹쳐 순간적으로 DB 부하 및 병목 현상이 발생할 수 있다.
  이를 방지하기 위해 전체 거래를 스캔하는 복잡한 집계 쿼리는 MyBatis로 인덱스를 타도록 설계하고, 조건에 맞는 대량의 매도 주문 생성 로직은 JPA를 활용하는 하이브리드 방식으로 역할을 분리하여 처리 효율을 높인다.


# 시스템 처리 흐름
[ API 처리 흐름 ]
- 매수 진입      : Redis 중복 체크         --> MariaDB Lock( 동시성 제어 ) 획득     --> 예수금 차감 및 주문 생성 ( DB 트랜잭션 종료 )     --> 증권사 API로 매수 요청 전송
- 체결 갱신      : 증권사 체결 결과 수신    --> Redis 중복 처리 검증                 --> 주문 최종 체결 상태 갱신 ( JPA 변경 감지 활용 )

[ 정산 처리 Bactch ]
- 정산 배치      : 짧은 주기로 체결 완료된 미정산 내역 분할( Chunk ) 조회             --> 수수료 및 세금 정산     --> 유저 잔고 일괄 반영 ( MyBatis 대량 삽입 처리 )
- 반대매매 배치  : 장 마감 후 유저 계정별 미정산 거래 내역 전체 탐색( MyBatis )        --> 위험 대상 색출         --> 익일 시장가 매도 주문 일괄 생성 ( JPA )


# 기술 스택
- Language & Framework : Java 1.8, Spring 4.2.7 ( Legacy Java Config 기반 )
- Database             : MariaDB 10.6, Redis, H2
- ORM                  : MyBatis 3.5 및 JPA
- Batch                : Spring Batch 3.0
- WAS & Build          : Tomcat 9.0, Maven 3.8
- CI/CD                : Jenkins, Docker
- Test                 : JUnit 5, JMeter, Postman
- Logging              : Logback 1.2
